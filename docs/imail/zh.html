它能做什麼

協定、信箱、管理與憑證都在同一個容器裡。

標準連接埠上的郵件協定

25 的 SMTP（STARTTLS）、587 submission、465 SMTPS、993 IMAPS、110 POP3（登入前必須 STLS）與 995 POP3S；網頁介面用 80 與 443。

網頁信箱

資料夾、搜尋、對話檢視、回覆、全部回覆、轉寄、附件下載，以及淺色／深色主題。七種介面語言——聯合國六種正式語文另加繁中——在瀏覽器裡切換。

多網域、使用者與配額

一個主要網域加上多個附屬網域、每個信箱的配額，以及管理使用者、網域、DNS 紀錄與憑證的管理台。

憑證

HTTP-01、手動 DNS-01 或 Cloudflare token 的 ACME，也可以上傳憑證。每個網域可以有自己的憑證，ACME 的兩種流程會自動續期。

送信信譽

DKIM 簽章、SPF 檢查、DMARC 與 PTR 指引，外加可調的垃圾郵件過濾等級。外送時會驗證對方伺服器的憑證。

一個資料目錄

預設 SQLite，較大的安裝可用 MySQL 或 PostgreSQL。設定、資料庫、DKIM 金鑰與憑證都在 config/ 底下，備份就是複製目錄。

部署到 VPS

需要 Docker + Compose、一個 public IPv4 和／或 IPv6，以及你自己控制 DNS 的網域。HTTP-01 需要對外開放 80。

抓原始碼並建立資料目錄

config/ 就是整台伺服器的狀態：設定、SQLite、DKIM 私鑰與 TLS 材料。

git clone https://github.com/noelbennettz/imail.git
cd imail
mkdir -p config

啟動已發佈的 image

這會拉 ghcr.io/noelbennettz/imail:latest，並發佈八個郵件與網頁 port。要綁哪個位址、用哪些 port、./config 放哪裡都可以改；每個參數的意義寫在 DOCS.md，repo 裡的 docker-compose.example.yml 把每個 port 與 volume 都逐行註解好了。

docker compose -f docker-compose.ghcr.yml up -d
docker compose -f docker-compose.ghcr.yml logs -f imail

完成安裝精靈

開 http://your-server-ip/，輸入容器啟動時印出的安裝 token：執行 docker compose logs imail，從開頭是 *** Setup token: 的那一行複製 24 個字元的 token。接著精靈才會詢問資料庫、管理員、網域、DNS 紀錄與 TLS。token 只存在記憶體，精靈的每個請求都要帶，初始化完成後即消失；它能阻止陌生人搶先完成安裝，但不會加密管理員密碼，所以仍請在可信網路完成。

先確認 25 port，再開始除錯。很多 VPS 擋 outbound TCP 25，信就寄不出去；inbound 25 沒開則外網的信進不來（MX 沒有 port 欄位）。兩者都要請供應商處理。 Rootless Docker 不能綁 1024 以下，請改成高埠映射（8080:80、18443:443…）。

DNS 紀錄與 TLS

安裝精靈會給每個網域精確的值；下面是這些紀錄的形狀。

  • 郵件主機要有 A 與 AAAA。只加伺服器實際擁有的族別；會收信的每個網域都要有自己的 MX、SPF、DKIM 與 DMARC。
  • PTR 在 VPS 設定，不在你的 zone。把反解指到 smtp.example.com，收件方才能確認寄件主機。
  • 憑證要涵蓋用戶端會用的每個名字。通常是 apex 加上 smtp.、imap.、pop. 與網站網域。
  • 憑證的取得方式。HTTP-01、DNS-01（手動或 Cloudflare token）或上傳。HTTP-01 與 Cloudflare 會自動續期。
@                  A/AAAA  203.0.113.10 / 2001:db8::10
mail               A/AAAA  同一個位址
smtp               A/AAAA  同一個位址
@                  MX      10 smtp.example.com.
@                  TXT     "v=spf1 a mx ~all"
default._domainkey TXT     "<安裝精靈產生的值>"
_dmarc             TXT     "v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com"

傳播比精靈慢。先用 dig +short MX example.com、DKIM 的 TXT、_dmarc 與 dig -x <server-ip> 確認，再開始怪伺服器。

先知道的限制

在改 MX 之前，決定這台伺服器適不適合你的事。

  • 25 port 決定能不能收發。外網寄信只會連 inbound 25（MX 沒有 port 欄位），寄外需要 outbound 25；很多主機商兩邊都封，替代 port 只對你自己設定的用戶端有用。
  • 帳號名稱在網域之間是唯一的。alice@one.example 與 alice@two.example 不能並存，請改成 alice 與 alice-sales。
  • TLS 要用用戶端連線的名字。SNI 檢查嚴格，用戶端連的每個名字都必須在憑證裡。放在反向代理後面時，要保留 SNI 與公開主機名。
  • 不是所有憑證都會自動續期。HTTP-01 與 Cloudflare DNS-01 會；手動 DNS-01 與上傳的憑證要自己換。

一台伺服器，一個資料庫。SQLite 適合單機小規模；需要外部資料庫的部署才選 MySQL 或 PostgreSQL。 只有 IPv4 或只有 IPv6 的主機都能跑；送到主機沒有的位址族時，會當成一般的暫時性錯誤。

安全預設

密碼、TLS 與第一次啟動時，伺服器實際的作法。iMail 目前是 beta：版本之間可能不相容，升級前請先備份 config/。

密碼與 session

密碼以加鹽的 PBKDF2 雜湊儲存，至少 8 字元；改密碼會撤銷所有現有 session。

全程 TLS

只支援 TLS 1.2 與 1.3；IMAP 不會在沒有 TLS 的情況下提供；外送時對方憑證驗不過就回報失敗，不會退回明文。

第一次啟動與機密

config/config.json 以 0600 寫入。安裝精靈只在第一次成功初始化之前存在，而且它的 API 需要容器日誌印出的一次性安裝 token：請在可信網路完成，備份 config/，但不要 commit。

回報安全性問題

請用 GitHub 的 Security 分頁與 Report a vulnerability。若該表單不可用，開一個標題為「Security contact request」、不含任何技術細節的 issue。SECURITY.md 列出支援的版本與範圍；不承諾回應時限。

常見問題

把 MX 指到新主機之前，值得先知道的事。

這是郵件伺服器，還是只有網頁信箱？

兩者都是。iMail 處理 SMTP、submission、SMTPS、IMAPS、POP3/STLS 與 POP3S，同時提供網頁信箱與管理台。任何標準郵件軟體都能連，日常收發信不需要網頁介面。

VPS 擋 25 port，還能用嗎？

不完全能。其他郵件伺服器只會連 25——MX 紀錄沒有 port 欄位——所以 inbound 25 被封就收不到外網的信，只能前面放 relay 或一台 25 開著的機器。自己人仍可用 587 投稿，寄外則需要 outbound 25 或 relay。

多網域時怎麼登入？

只有一個網域時，alice 與 alice@example.com 都可以。兩個網域以上必須用完整位址，因為裸名稱會有歧義。帳號是全域唯一：alice@one.example 與 alice@two.example 不能並存，請命名成 alice 與 alice-sales。

一定要用它申請的 ACME 憑證嗎？

不用。HTTP-01、手動 DNS-01、Cloudflare DNS-01 與上傳 PEM 都支援，可全域或每個網域分開。自動續期只適用兩種 ACME 流程；上傳的憑證要自己注意到期。

可以放在 TLS 反向代理後面嗎？

可以。把 httpsEnabled 設成 2（HTTP-only），讓代理終結 TLS。session cookie 只在 HTTPS 啟用時標 Secure，所以代理必須可信。

要備份什麼？

整個 config/：config.json、SQLite 資料庫（或你的 DSN）、DKIM 私鑰與憑證目錄。複製到新主機，伺服器就回到原本的樣子。

IPv6-only 或 IPv4-only 主機可以跑嗎？

可以。只有 IPv4、只有 IPv6 或雙棧的主機都能跑；啟動時若設定的位址族不存在，會改用另一族並記錄原因。只存在於缺少那一族的目的地無法送達，會回報為暫時性失敗。

為什麼是 AGPL？

自架、fork、收費支援都可以。但如果你把修改過的 iMail 當成網路服務給別人用，使用者必須能取得你實際執行版本的原始碼——這就是第 13 條。
